# 問題 3：比較有 AGENTS.md 與沒有 AGENTS.md

## 結論
兩次獨立 Agent 都能主動檢查資料、產出可執行程式與合理圖表，主要數值結論一致。有規範的版本更貼近小組指定的目錄、版本化輸出與多重視覺編碼；本次沒有證據顯示它在所有分析面向全面優於無規範版本。

## 實驗設計與兩個步驟
1. 第一次：在獨立工作目錄 without_agents/ 放入 data.csv，不放小組 AGENTS.md，交由全新 Agent 執行。
2. 第一次完成後，第二次：在另一獨立工作目錄 with_agents/ 放入位元組相同的 data.csv 與小組原有 AGENTS.md，交由另一個全新 Agent 執行。

兩個 Agent 均未繼承本對話，且被要求只查看各自目錄、不讀其他實驗結果、不操作 GitHub。兩次使用相同工具環境與相同任務 Prompt；共享的操作邊界還包括保護輸入、實際執行、保留成果與回報驗證。這不是完全沒有任何系統指令的對照，而是沒有小組專案規範的對照。

## 完全相同的任務 Prompt
「請分析 data.csv 中的重要趨勢，並製作適合的資料視覺化。」

資料為演算法效能 CSV：224 筆、7 欄、4 種演算法、7 種輸入大小、各 8 次測量。兩份輸入與原始 CSV 的 SHA-256 均為 8285b2903f318ef452e7706b627a9f4bf6bc21cd6e72ba858c14c57d92a2136a；第二次規範與共用 AGENTS.md 完全相同，沒有為了結果修改規範。

## 分析結果與方法差異
- 兩次有效耗時都是 222 筆、記憶體 224 筆、比較次數 223 筆。均只排除該指標的缺失或無效值，不刪除整列，且均保留 18 筆 0.05 ms 與 420 MB 記憶體值。
- n=100,000 時，兩次得到相同中位耗時：二分搜尋 7.0290 ms、線性搜尋 179.6865 ms；中位耗時比約 25.56。此為觀測值，未含已知的前置排序成本說明，不能直接泛化。
- 快速排序中位耗時 157.4740 ms，合併排序 199.5465 ms，前者低約 21.1%；記憶體中位數分別為 27.915 與 42.490 MB，前者低約 34.3%。
- 異常標記策略不同：第一次對各演算法/輸入組使用 1.5×IQR，標記 14 筆記憶體候選；第二次使用「中位數 + 10×MAD」，標記 1 筆極端值。候選數不同源自方法與目的不同，不代表其中一個自動較正確；兩次均保留所有記憶體量測。
- 圖表語言不同是 Agent 自行選擇；AGENTS.md 只要求所用語言字型可讀，沒有規定必須中文，第二次英文標籤不構成違規。
- 第一次程式使用固定輸出檔名，重跑會更新同名成果；第二次採版本號保留。第一次沒有小組規範，這是行為差異而非它違反不存在的規則。

## 驗證證據
- 兩次 Agent 均實際執行程式並回報驗證。原始輸入雜湊相同，均保持不變。
- 第一次 validation.json 記錄四圖解碼、資料筆數與輸出；第二次 validation_v1.json 記錄 28 組重算、三圖解碼與 HTML 內嵌檢查。
- 整理者再次核對最大規模的摘要與原始資料一致，檢視兩次全部七張 PNG，確認可解碼、文字與圖例可閱讀。
- 所有檔案清單與 SHA-256 見 artifact_manifest.json；工作設計見 experiment_design.json，視覺檢查見 visual_review.md。

## 限制與反思
- 每個條件只有一次獨立 Agent 任務，模型生成具有變動性；不能以此證明規範必然造成所有差異，或估計普遍改善幅度。
- 無規範不代表 Agent 沒有通用知識、系統規則或共同的安全邊界；兩次都已被要求實際執行和保護輸入。
- 沒有重做不同長度 Prompt、耗時或 token 成本對照，不宣稱節省比例。
- 零耗時被當成不可判讀值而排除，是兩次共同的分析假設，不是已證實的資料錯誤；有規範版本另做敏感度比較。
- 問題 1、2 的先前時間圖使用平均值且保留零耗時；問題 3 使用有效正耗時的中位數。不同清理與彙整策略的數值不能直接混為同一分析結果，先前成果保留原樣。
- 規範可再明確化零耗時處理、異常標記目的與圖表語言。本次維持原規範不變，避免改動實驗條件。
- 封存證據位於儲存庫 experiments/question3/；實驗實際執行於原本兩個隔離目錄。若直接在 GitHub 專案內重跑，可能繼承上層 AGENTS.md，不能將那次重跑當成無規範實驗。
